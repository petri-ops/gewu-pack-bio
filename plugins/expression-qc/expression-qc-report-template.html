How to Interpret This Report

  • VALID — every gate passed. The filtered matrix (validated_counts.csv) is ready to feed into deseq2.
  • WARNING — the analysis completed, but at least one check raised a scientific concern (for example: non-integer counts suggesting TPM/FPKM or pre-normalized input, duplicate gene IDs, large library-size spread, low-correlation or PCA-outlier samples, missing metadata alignment). The result remains usable; review each warning and confirm manually. This tool never deletes samples or genes on its own beyond the recorded expression filter.
  • BLOCKED — a hard gate failed (missing counts file, fewer than 2 sample columns, non-numeric columns, NA/Inf values, negative counts, or fewer than 10 genes remaining after filtering). Do not model this matrix; fix the input first.
  • Filter rules are recorded, not silent — the low-expression filter shown in the Filter Rules section above is applied exactly as stated, and the same rule is written to gene_filter_statistics.csv so downstream readers can reproduce it.

Methods Summary

Quality control only: orientation and numeric-integrity checks on the raw matrix; an expression filter keeping genes with count ≥ min_count in at least min_samples samples; library-size uniformity; Pearson correlation on log2(counts+1); and SVD-based PCA on filtered log2 counts. Correlation and PCA outliers are reported as flags for manual confirmation — the pipeline decides nothing about sample removal.

Caveats: (1) non-integer counts usually indicate TPM/FPKM or pre-normalized input — DESeq2 expects raw integer counts, so re-export raw counts if possible; (2) a correlation or PCA outlier is a flag, not a verdict — check batch, library-prep date and biology before acting; (3) QC validates data quality only and makes no claim about whether the contrast of interest is statistically detectable.
