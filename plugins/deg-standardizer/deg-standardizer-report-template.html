Standard Output Schema

Every standardized table (deg_standardized.csv) carries exactly these columns:

ColumnMeaning

How to Interpret This Report

  • VALID — all required columns were found and the table standardized cleanly. The thresholds applied are the ones shown in the Filter Rules section above.
  • WARNING — standardization completed with recorded caveats: missing gene IDs (rows excluded), missing effect sizes or p-values (kept, flagged), missing padj (marked non-significant), duplicate gene IDs, or zero significant genes. Note that an empty significant set is a valid scientific result, not a tool failure.
  • BLOCKED — a required input is missing: no DEG result file, a missing gene/effect/pvalue column, or — most importantly — a missing padj column. Without FDR-controlled padj the tool refuses to guess significance; switch to an upstream method that produces padj.
  • ranked_genes.csv keeps everything — the ranked list contains ALL genes ordered by padj then |log2FoldChange|, not only the significant ones, so it can feed GSEA-style methods directly.

Methods Summary

Column mapping only — no statistics are recomputed. The configured gene/effect/pvalue/padj columns are projected onto the fixed schema; direction is derived from the sign of the effect size; significance is the conjunction of padj < padj_threshold and |log2FoldChange| ≥ effect_threshold; ranking is a stable sort by padj then by absolute effect size. Thresholds belong to the caller and are recorded verbatim in filter_summary.json.

Caveats: (1) this tool standardizes and gates — it does not re-run or correct the upstream differential test; (2) rows with missing padj become non-significant by construction (padj = 1), so an upstream method lacking FDR control will silently yield zero significant genes — prefer an upstream that reports padj; (3) threshold choices (padj, |log2FC|) are scientific decisions — changing them changes the artifact, and both old and new values are recorded.
